WHY THIS EXISTS
---------------
15 of the suite's 33 steps ship with empty expectations, because the *shape* of
`show evpn global` or `show evpn mac address-table` output cannot be known from
the documents — the CLI doc gives syntax, not layout. `ate capture` runs exactly
the commands the generated scripts need against a real device and records what
comes back, closing the loop:

    documents -> plan -> code -> DEVICE -> expectations -> code

HOW TO USE IT WHEN AN EVPN BUILD EXISTS
----------------------------------------
   Point it at the device; usable captures land in the JSON keyed by the
   `EvpnParams` constant they fill:

     ate capture --host <dut> --jump <box> --out out/captured_expectations.json

   Only OK captures are offered. EMPTY (ran, returned nothing) and UNSUPPORTED
   (rejected) are recorded with their reason but never become expectations.
   Every capture is stamped with host, software build and the command that
   produced it, so an expectation is reviewable rather than magic.
