DO NOT ACT ON THE CONFIG HALF YET
----------------------------------
The config-mode probes are demonstrably unreliable. `l2-services evpn %s
mac-limit %s` is reported MISSING, yet the device itself lists `mac-limit`
under `l2-services evpn evi-1 ?` — we read that completion by hand, and we
configured an EVI successfully in the same session. So at least one of the 48
"missing" config verdicts is a false negative, and none of them should be acted
on until the probe is fixed.

Two bugs were already found and fixed in this area, which is why the
operational half is now sound:

  1. Mode drift. A `?` completion on a config path DESCENDS into that submode,
     so every later probe was evaluated from wherever the previous one landed.
     Fixed by returning to `top` before each config probe.
  2. Buffer desync. The reader could match a prompt left over from the previous
     probe and return immediately, attributing responses to the wrong command.
     The evidence was unambiguous: `l2-services evpn X ?` came back as the
     single token `port-based`, a fragment of the preceding probe. Fixed by
     draining the channel before every send.

Something in the config path still perturbs the completion listing — most
likely the candidate configuration accumulating nodes across ~57 probes in one
session, since each `?` both lists AND descends. The fix direction is a fresh
`configure`/`abort` cycle per probe, or reading `show configuration` instead of
trusting completions after the first descent. Not done.

WHY THIS IS REPORTED RATHER THAN QUIETLY FIXED
-----------------------------------------------
A verifier that lies about which commands exist is worse than no verifier: it
sends someone chasing 48 non-bugs and erodes trust in the 31 real ones. Both
sweeps that produced suspect output were discarded rather than published, and
this file states the trust boundary explicitly.

The tool reports; it never rewrites the registry. Which spelling is correct is
a judgement about the product across builds — and this DUT was re-imaged
mid-session, with LAB 904 and LAB 22 disagreeing about whether EVPN existed at
all.
