1. WHAT "MISSING" MEANS, AND WHAT IT DOES NOT
--------------------------------------------------------------------------------
`missing` means this build does not offer the command. It does NOT mean the
CLI documentation is wrong — a document may simply be ahead of the build. The
tool reports; which spelling is right is a judgement about the product and
belongs to someone who can see both the device and the specification.

Three verdicts, deliberately distinct:

    supported   the parent path lists the token
    missing     the path or the token is genuinely absent from this build
    unknown     the sweep COULD NOT ASK - see section 3

The registry is never rewritten from a sweep.


2. THE BUG THAT MADE THE CONFIGURATION HALF LIE
--------------------------------------------------------------------------------
A `?` on a *leaf* does not list-and-return. The device starts asking for the
VALUE, and no prompt is coming:

    l2-services evpn X service-type ?
    Possible completions:
      vlan-based
      port-based[vlan-based]
    [port-based,vlan-based]:            <- the device is waiting

Range leaves do the same, over several lines:

    l2-services evpn X mac-limit ?
    (<1-250000>    maximum MAC learned (default 65520)
      Currently configured):

The reader did not recognise that as "waiting", so it burned its full timeout
and returned a partial buffer — and the device's answer stayed in the channel
until the NEXT probe collected it. From that point on every verdict described
the wrong command. That is why `l2-services evpn %s mac-limit %s` was once
reported missing on a device that demonstrably has `mac-limit`.

Three fixes:

  * the value prompt is recognised as a waiting state;
  * it is escaped with Ctrl-C, which the device answers `Error: user aborted`.
    The prompt is NEVER answered — answering is a write to a live device, and
    this stage is read-only;
  * after every probe the sweep proves the channel is back at its prompt, and
    re-opens the shell if it is not. This run needed **0** recoveries.

Two smaller reading errors were fixed at the same time:

  * the device appends a leaf's current value to its own name with no
    separator, so `port-based[vlan-based]` IS the token `port-based`. Compared
    raw it never matched, and a correct command read as missing.
  * templates that spell an argument `<value>` instead of `%s` were being
    probed for a literal token `<value>`, which no device will ever offer. Those
    five could only ever report missing, on any build.


3. "UNKNOWN" — THE PROBES THAT CANNOT BE ASKED (8)
--------------------------------------------------------------------------------
All eight are the BGP EVPN address-family templates:

    routing bgp %s vrf %s neighbor %s af-l2vpn evpn ...

The sweep substitutes a placeholder for each argument, and the device rejects
it as a key before the path is ever walked:

    routing bgp X vrf X neighbor X af-l2vpn ?
    syntax error: "X" is not a valid value.

`af-l2vpn evpn` **does exist** on this build — with a real AS number and a real
neighbour address the device offers `evpn` and `vpls`:

    routing bgp 100 vrf default neighbor 1.1.1.1 af-l2vpn ?
    Possible completions:
      evpn
      vpls

Reporting those as `missing` would send someone to fix commands that are
correct, so they are reported as unaskable instead. Worth noting from the same
probe: `af-l2vpn` appears **only under a neighbour or neighbour-group, and only
in `vrf default`** — it is not a VRF-level node, and a non-default VRF does not
offer it.

5. WHAT THIS BUILD DOES NOT HAVE, THAT THE DOCUMENTS DESCRIBE
--------------------------------------------------------------------------------
The EVI node offers exactly five children:

    l2-services evpn <name> ?
      auto-discovery   interface   mac-aging-time   mac-limit   service-type

so `control-word`, `host mac-address-duplicate-detection`, `Advertise-mac`,
`unknow-mac-flooding` and `es-waiting-time` are **not configurable here**. They

`lacp-key` / `lacp-system-mac`: the EVPN multi-homing configuration is absent
from LAB 22. That is the largest single block of `missing` verdicts.

`service-type` accepts `port-based` and `vlan-based` only.

`show evpn bum routing-table`, `show evpn ethernet-segments`,
