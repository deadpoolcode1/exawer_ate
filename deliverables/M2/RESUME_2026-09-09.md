## Two device facts every run has to work around

**1. Deleting an EVI aborts bgpd.** `assert (_Bool)(ipi_evi_p)`,
`bgp_evi.c:310`, `bgp_evi_delete`. The service then survives in operational
state after leaving the configuration:

```
no l2-services evpn evi-1 ; commit  ->  Commit complete.
show configuration l2-services      ->  % No entries found.   (gone)
show evpn summary                   ->  EVPN NAME: evi-1      (still there)
```

Only a reboot clears it, so only the first test after a reboot can start from
the state it asserts. This is why the tests cannot simply run back to back.

**2. The ONL hostname.** Exaware's bring-up matches the ONL shell by the
literal `"@localhost"` (`CmpCliSession.java:69`). The router application
rewrites the hostname to `router` late in boot, and then bring-up cannot enter
ONL mode at all. Set it after the box settles:

```
ssh root@10.3.99.10 (password root)   # the ONL host
hostname localhost
```

`/etc/hostname` does not survive: the application rewrites it.

**3. Their syslog check pages.** Bring-up runs
`less /var/log/syslog | grep ... -c` on the serial TTY. Once the syslog is
more than a screen, `less` waits for a keypress and the command times out at
100 s. `: > /var/log/syslog` before a run avoids it.

## What was fixed in the generator today

All device-verified, all committed:

1. **The tester's core interface was assumed, not created.** `set intf
   $vp/interface:1` is a path, not an object; OSPF ended up with a null
   `protocolInterface` and the tester had no address on the core link. This
   was the real reason BGP sat in Active.
2. **Traffic items were built in the wrong order.** No `configElement` exists
   until `generate` runs.
3. **AC vports had no interface**, so endpoint sets had no sources.
4. **With an `.ixncfg` loaded the suite rebuilt the items** instead of using
   them, leaving them unapplied.
5. **`generate` is required after loading the `.ixncfg`**, or the hardware is
   never armed: items report `state=started` with correct MACs and every
   circuit counts zero.
6. **A raw item needs a real destination MAC.** The default is
   `00:00:00:00:00:00`; this build has `Unknown MAC Flooding: Disabled` and no
   CLI to enable it, so that frame is taken by the port and dropped before the
   bridge domain. Broadcast is flooded and the source MAC is learnt.
7. **New `TESTER_PROTOCOLS` step**: loading an `.ixncfg` restores OSPF/LDP/BGP
   but leaves them stopped. The step starts them and asserts each is running.
