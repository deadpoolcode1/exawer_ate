======================================================================
OPEN 1: frames reach the DUT port, not the attachment circuit
======================================================================
pc-3099 (10.3.99.1), 8.7.0 LAB 935. Chassis 10.1.70.108, IxNetwork 9.00.

WORKS
  .ixncfg loads at bring-up, three vports up, tester OSPF/LDP/BGP started.
  DUT:  show ospf neighbor -> 29.60.0.2 Full/ -  x-eth0/0/18
        show bgp neighbor  -> 29.60.0.2 up       IPv4u
  Traffic transmits: x-eth0/0/32 went from 27.0 M to 519.6 M packets in
  one run.

DOES NOT
  x-eth0/0/32.1001   RX 0   TX 0
  x-eth0/0/40.1002   RX 0   TX 0
  x-eth0/0/40.1003   RX 0   TX 0
  show evpn mac-address-table -> legend only, no MACs

  Frames arrive on the port and are not classified onto the sub-interface.

RULED OUT
  1. Missing VLAN header. It is there, read off the chassis:
       TI_AC1_TO_AC2  ethernet-1, vlan-2 (VLAN=1001), fcs-3
       TI_AC2_TO_AC1  ethernet-1, vlan-2 (VLAN=1002), fcs-3
       TI_AC3_TO_AC1  ethernet-1, vlan-2 (VLAN=1003), fcs-3
     -auto false, so a fixed value, not a counter.

  2. Double tagging. Removing the raw header and letting the vport
     interface tag the frame gave the same zero: a raw item does not
     inherit the interface VLAN, it just sends untagged. The header push
     is required and is back.

  3. Building the endpoints the other way. With vlanEnable=false,
     ixia_lib's configTrafficItemEndpoints dies inside `ixNet commit`.
     vlanEnable=true is the only branch that works.

NEXT
  Either the DUT discards the tagged frames (TPID, or a port mode needed
  under l2-transport), or the sub-interface counters do not increment on
  this platform. The empty MAC table says the frames genuinely do not
  reach the EVI, so it is not only a counter artifact.

  This is the one thing between the suite and a green TC02.
